# Day 03 — 2026-10-04 — Project B: video strategy reconstruction (tomtrades gold + DXY)

## Request
Reverse-engineer the method in *"I Made $1.4M Trading Gold, Here's What Actually Works"* (tomtrades,
youtu.be/xSVlVpXLuV0) into a specification and an MQL5 EA, with research documents, tests, backtests and a
video-vs-EA validation report. The request is explicit approval for MQL5 work (tester/demo only); live trading is still
not approved.

## Access (what worked, what did not)
- YouTube blocks this sandbox's IP for the page and media ("Sign in to confirm you're not a bot", HTTP 403 on stream
  URLs). PyPI is blocked; `yt-dlp` was taken from GitHub releases.
- **Worked:** oEmbed metadata; `yt-dlp` with the `web_embedded` client for the full auto-captions (186 events,
  00:00–11:40) and the info JSON (chapters); the storyboard (`sb0`, 141 frames, 320×180, one per ≈4.96 s).
- **Did not work:** the video stream itself → no frame above 320×180. Prices, clock times and the chart header are
  unreadable. Stated in every research document.
- Supplementary: captions of 9 other videos by the same author (S1–S9) to define his own terms, incl. the 8.5-hour
  course. No transcript text is committed; only short quotes with timestamps.

## Hypotheses
- **H-12 REJECTED as implemented.** The DXY "entry-model inversion" filter did not improve expectancy or win rate in a
  meaningful way (+1.3 pp win rate; EV unchanged). The author's 64% → 82% claim is not reproduced.

## Tests (commands + outputs)
- `python -m pytest -q` in CI (`tests` workflow), run 37216364081 at `b704271`: **98 passed in 4.34s**.
  Includes: causality by truncation and by scrambling the future (3 variants), extension tracker vs. brute force,
  pivots, zig-zag, MTF classification, DST session windows, DXY formula, exit simulation, risk sizing, report metrics,
  and the six video-example fixtures for pivot strengths 1, 2, 3 plus the H1_AND_M15 mode.
- Local `pytest` is not possible in this sandbox (no numpy/pandas; PyPI blocked), so every test result above comes
  from CI.

## Mistakes caught and fixed (kept for honesty)
1. CI installs pandas 3, whose datetime indexes default to microseconds; `.asi8` returned µs while the engine assumed
   ns (setups landed in 1970). Fixed with explicit `as_unit("ns")`.
2. A fixture with a 14-point jump spliced into the history inflated the ATR so the zig-zag missed the pullbacks; the
   test data was fixed, not the engine.
3. Hand-checking the fixtures showed that a shallow dip is not a pivot for strength 3 and that one MTF fixture sat at a
   0.752 ratio (threshold 0.75); fixtures were redesigned before the first CI run of the examples.
4. My expected drawdown in a new report test was wrong (400 vs. the correct 450).
5. The spec contradicted itself (SHF-4 "new extreme restarts" vs. SHF-5 "one signal per direction"); resolved as
   "one evaluation per extreme".
6. PULLBACK_50 sizing: a re-anchored limit could raise risk above 0.20%; both implementations now size for the worst
   admissible limit.
