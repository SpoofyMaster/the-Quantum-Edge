## What 7.01 did with it
The pattern itself (late T1, rejection, two closes below the T1 wick) was already the reversal. Three things stood in
the way:
- **The window.** The 240-bar setup window counted from the BPR's creation, so a first tap after 4 hours (M1) was lost
  (the setup was EXPIRED in WAIT).
- **The warm-up.** It dropped every BPR formed in the 5000 history bars at the start.
- **Speed.** By default the limits waited for a pullback candle (`InpAnticipateEntries = false`). The reversal also
  waited for an FVG of the drop after its 100 %. So the limits could come one or more bars after the second close.

## v8 (MQL5 only; the research defaults and the parity set unchanged)
**Detector.** `t1WaitBars` (EA `InpMaxBarsToT1`, EA default 0 = no limit; detector default −1 = v7 rules).
With ≥ 0:
- **Expiry before T1.** Only `t1WaitBars` applies before T1 (`Expired()`).
- **The window.** The breakout window counts from T1; a reversal setup counts from its last rejection when later.
- **Capacity.** At 128 setups the oldest setup still in WAIT makes room (`EvictOldestUntouched`, DONE(CAPACITY)).
- **Warm-up.** Setups in WAIT / ZONE / BREAK at the warm-up's end go on.

`revNeedFvg` (EA `InpRevNeedFvg`, EA default false; detector default true): the reversal's `FvgOk` is true, so with
`anticipate` its limits go in on the confirming close.
