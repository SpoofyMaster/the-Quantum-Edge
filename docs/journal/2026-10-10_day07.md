## Work done (MQL5 only, as asked)
**Three new inputs in `mql5/BprFvgEA/BprFvgEA.mq5`, version 3.00.** All default to `true`, so v3 behaves exactly like
v2.

| Input | When `false` |
|---|---|
| `InpUseCostFilter` | The executor passes `maxCostR = 0` (off) to the detector. No `SKIP (COST)`. |
| `InpUseRRFilter` | The executor passes `minRR = 0` (off). No `SKIP (RR)`. Note that `InpMinRR` already defaults to 0. |
| `InpCancelAtSessionEnd` | `BuildEnv` never sets `env.sessionCancel`. Pending orders are not cancelled at 14:45 New York and stay until they fill, the leg expires or a new extreme re-anchors the setup. |

**Unchanged:**
- **The entry window.** New orders after 14:45 still need `InpUseSession = false`.
- **The 16:44–17:00 New York rollover deletion of pending orders.** A fill there would be closed at once by the 16:44
  flat. It now logs `ROLLOVER` explicitly and is counted on the panel. Its record reason stays `SESSION_END`, so the
  pure codes are unchanged.
- **The hard limits:** 0.20 % per setup, 1 % daily, 120-min time stop, tester / demo only.

**Other changes:**
- **Visibility.**
  - A new panel row 3, `switches: …`; the panel now has 11 rows.
  - A `start v3:` log line.
  - A `SELF-CHECK switches` line, plus a note when the cost filter is off.
- **The pure detector and the Python reference are unchanged.** The switches are mapped in the executor. The parity
  harness therefore still covers the default rules, and the cost and RR switches equal `max_cost_r = 0` /
  `min_rr = 0` in the reference.
- **Docs:**
  - README: a v3 section, the input rows and the panel table;
  - spec §8: "EA-only switches (v3)".
