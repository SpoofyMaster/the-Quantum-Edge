# Day 04 — 2026-10-07 — Project C: Balance Price Range from "ICT Concepts [LuxAlgo]"

## Request
The user pasted the full Pine v5 source of *ICT Concepts [LuxAlgo]* and asked for three things:
- understand all of its parameters;
- explain exactly how its **Balance Price Range** (BPR) is calculated;
- build it so it shows live on a chart.

This is a charting tool, not a strategy. No backtest was run and no claim about an edge is made. The request covers
MQL5 work: an indicator that never trades. Live trading is still not approved.

The LuxAlgo code is CC BY-NC-SA 4.0. Every derived file carries attribution and the same licence, and is
non-commercial.

## Work done

### Source and documentation
- `research/indicators/luxalgo_ict_concepts.pine`: the unmodified source, kept for traceability.
- `research/indicators/ICT_CONCEPTS_PARAMETERS.md`: every input and constant of the whole script, plus the per-bar
  order and an algorithm summary per module.
- `research/indicators/LUXALGO_BPR_SPEC.md`: the exact FVG/BPR algorithm.
  - **Revision 1** was mine.
  - **Revision 2** followed an independent re-derivation from the Pine source by a separate agent. It found:
    - **QUIRK 7 was wrong.** A consecutive-gap update can never change a BPR's left edge. It was rewritten.
    - The missing look-ahead warning for Present mode.
    - The broken-BPR case (QUIRK 6b).
    - Frozen entries beyond index 10 (QUIRK 11).
    - The IFVG update always breaks on its own bar.
    - Fibonacci with BPR off.
    - Pine runtime assumptions that were not labelled `HYPOTHESIS`.

### Three ports of the same specification
| Port | File | Notes |
|---|---|---|
| Python reference | `qe/indicators/luxalgo_bpr.py` | Standard library only. Bar by bar. Includes a forming-bar view that emulates Pine's realtime rollback, and Fibonacci-BPR. |
| MT5 indicator | `mql5/Indicators/LuxAlgo_BPR/LuxAlgo_BPR.mq5` | Chart objects. Live: a committed state plus a forming-bar copy on every tick. Optional "new BPR" alert and parity export. **Not compiled**: no MetaEditor here. |
| Browser replay | `tools/luxbpr_preview/` → `research/indicators/preview/LuxAlgo_BPR_live_replay.html` | Tick-by-tick replay on synthetic candles or a loaded MT5 CSV. Published as a private artifact. |

### Tools
- `tools/luxbpr_parity.py`: compares the MT5 export (`InpExportCSV=true`) with the Python reference.
- `tools/mql5_cpp_harness/`: transliterates the `.mq5` to C++, compiles it with g++ and drives it like MT5.
- `tools/mql5_static_check.py`: the MT5 indicator API names were added to its list of known built-ins.

## Adversarial review of the ports (3 auditors: MQL5 compiler, MT5 runtime/docs, Pine semantics)

The review produced 14 findings, all **minor**. The compiler auditor found no compile error. The Pine auditor found no
divergence between the Python reference and Pine; it found two wording errors in the spec. All 14 are fixed:

| Area | Fix |
|---|---|
| Box labels | Centred in bars, not in time, so weekend gaps no longer pull them off-centre. |
| Deleted boxes | Boxes deleted from outside are redrawn (the draw cache checks `ObjectFind`). |
| Chart background change | Boxes are re-blended at once (`OnChartEvent`). |
| Alerts | Also fire for bars committed during a full recalculation. Stale bars no longer alert: bars back-filled after an outage, and Friday's last bar when Monday opens. |
| Parity export | Rewritten after every full calculation. The file name includes the mode, and the log prints the real path (the agent folder in the tester). |
| Present window | Anchored by **time** at start, so scrolling back or a resync no longer moves it. Covered by a new harness case, which a mutation check confirmed it detects. |
| README | Shows the MT5 input captions and corrects the status table. |
| Python `run()` | New `forming_bar=True` option, which gives the same window as Pine/MT5 when a forming bar is shown. |
| Spec | IFVG chain wording corrected; the IFVG forming-bar non-monotone case documented. |

After the fixes: **66 passed** locally (`test_luxalgo_bpr.py` 43, JS parity 8, MQL5 harness 15).

## Limitations
- The `.mq5` has **not** been compiled in MetaEditor. The C++ harness checks its logic, not MQL5 syntax rules.
- Not compared against TradingView output. Parity rests on reading the Pine source; Pine runtime details are labelled
  `HYPOTHESIS` in the spec.
- Different data feeds give different gaps, so MT5 and TradingView charts will not show the same boxes unless the
  candles are identical.
- Only FVG/BPR, displacement and Fibonacci-BPR were ported. The other modules are documented only.
